# اقتراح: إعادة تصميم الصفحة الرئيسية كواجهة تفاعلية

**الحالة:** مقترح — بانتظار الموافقة قبل التنفيذ
**الملف المستهدف:** `web-frontend/modules/core/pages/workspace.vue`
**التاريخ:** 2026-07-29

---

## 1. المشكلة

الصفحة الرئيسية اليوم (`pages/workspace.vue`) هي **قائمة، وليست واجهة**. ما تعرضه:

| العنصر | المصدر | القيمة للمستخدم |
|---|---|---|
| اسم مساحة العمل + زر "إضافة جديد" | `selectedWorkspace` | تنقّل |
| "القوالب المقترحة" — بطاقتان | **ثابتتان في الكود** (`templates` ref، السطر 218) | تسويقية، لا تتغير أبدًا |
| "الموارد" — رابط API | إضافة من `DatabasePlugin` | ثابت |
| قائمة التطبيقات | `application/getAllOfWorkspace` | الفائدة الحقيقية الوحيدة |

ثلاثة من أصل أربعة أقسام **محتواها ثابت لا يتأثر ببيانات المستخدم**. المستخدم الذي يفتح
جداول كل صباح يرى نفس البطاقتين التسويقيتين اللتين رآهما في أول يوم، ولا يرى أي شيء عن
بياناته هو: كم جدولًا لديه، ما الذي تغيّر، أين توقّف بالأمس.

القسم الوحيد المفيد — قائمة التطبيقات — يعرض لكل تطبيق اسمه وتاريخ إنشائه فقط. تاريخ
الإنشاء معلومة تُقرأ مرة واحدة في العمر ثم تفقد قيمتها.

**الخلاصة:** الصفحة تُستهلك كنقطة عبور إلى الشريط الجانبي، لا كوجهة. الاقتراح هو تحويلها
إلى لوحة تُقرأ.

---

## 2. المبدأ الحاكم

> الصفحة الرئيسية تجيب على ثلاثة أسئلة: **ماذا لديّ؟** و**ما الذي تغيّر؟** و**أين أُكمل؟**

كل قسم مقترح أدناه يجب أن يجيب على أحدها. أي قسم لا يجيب على أحدها لا مكان له في الصفحة.

---

## 3. التصميم المقترح

```
┌──────────────────────────────────────────────────────────────┐
│  مساحة العمل ▾                              [+ إضافة جديد]   │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐   ← شريط الأرقام │
│  │ ١٢     │ │ ٤٧     │ │ ٨٬٣٠١  │ │ ٥      │                  │
│  │ قواعد  │ │ جداول  │ │ صفوف   │ │ أعضاء  │                  │
│  └────────┘ └────────┘ └────────┘ └────────┘                  │
│                                                              │
│  ▸ أكمل من حيث توقفت                        ← آخر ما فُتح     │
│  ┌──────────────┐ ┌──────────────┐ ┌──────────────┐          │
│  │ المهام       │ │ العملاء      │ │ الفواتير     │          │
│  │ قبل ٣ دقائق  │ │ أمس          │ │ قبل يومين    │          │
│  └──────────────┘ └──────────────┘ └──────────────┘          │
│                                                              │
│  ▸ قواعد البيانات                  ▸ آخر التغييرات            │
│  ┌────────────────────────┐        ┌───────────────────────┐ │
│  │ 📊 المبيعات            │        │ عبدالعزيز أضاف صفًا   │ │
│  │    ٤ جداول · ١٬٢٠٠ صف  │        │ في "المهام" · ١٠:٣٢   │ │
│  ├────────────────────────┤        ├───────────────────────┤ │
│  │ 📊 الموارد البشرية     │        │ سارة عدّلت "الحالة"   │ │
│  │    ٧ جداول · ٣٤٠ صف    │        │ في "العملاء" · ٠٩:١٥  │ │
│  └────────────────────────┘        └───────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

### الأقسام الأربعة

**١. شريط الأرقام — «ماذا لديّ؟»**
أربع بطاقات: عدد قواعد البيانات، عدد الجداول، مجموع الصفوف، عدد الأعضاء. كل بطاقة قابلة
للنقر وتنقل إلى الموضع المقابل. هذا هو العنصر الذي يحوّل الصفحة من قائمة إلى لوحة.

**٢. «أكمل من حيث توقفت» — «أين أُكمل؟»**
آخر ٣–٦ جداول فُتحت، مرتبة بالأحدث. هذا القسم وحده يختصر على المستخدم اليومي رحلة
"الشريط الجانبي ← قاعدة البيانات ← الجدول" إلى نقرة واحدة.

**٣. قواعد البيانات — بديل القائمة الحالية**
نفس القائمة، لكن ببيانات حقيقية بدل تاريخ الإنشاء: عدد الجداول ومجموع الصفوف لكل قاعدة.

**٤. آخر التغييرات — «ما الذي تغيّر؟»**
تدفّق بآخر التعديلات على مستوى مساحة العمل: من غيّر، ماذا، وأين، ومتى.

### ما الذي يُحذف

- **البطاقتان التسويقيتان الثابتتان** (`project-management` و `performance-reviews`
  المكتوبتان في الكود). القوالب تبقى متاحة من زر "إضافة جديد ← القوالب الجاهزة"، وهو
  مكانها الصحيح: عند الإنشاء، لا في كل زيارة.
- **بطاقة "الموارد"/API** كقسم مستقل — تنتقل إلى تذييل خفيف أو إلى قائمة المساعدة. رابط
  للمطوّرين لا يستحق ثلث الصفحة الرئيسية.

## 4. ما الذي تحتاجه كل ميزة فعليًا

هذا هو القسم الحاسم في الاقتراح — **التكلفة ليست موزّعة بالتساوي**:

| القسم | مصدر البيانات | يحتاج تعديل خلفية؟ |
|---|---|---|
| عدد قواعد البيانات | `application/getAllOfWorkspace` في المتجر | ❌ متاح الآن |
| عدد الجداول | `application.tables` (محمّلة أصلًا) | ❌ متاح الآن |
| عدد الأعضاء | نقطة نهاية أعضاء مساحة العمل | ❌ متاح الآن |
| «أكمل من حيث توقفت» | سجل محلي في المتصفح (`localStorage`) | ❌ متاح الآن |
| **مجموع الصفوف** | `Table.row_count` — **موجود في النموذج، غير مُصدَّر في الـ serializer** | ✅ إضافة حقل واحد |
| **آخر التغييرات** | `rows/history.py` موجود **لكل جدول فقط** — لا توجد نقطة نهاية على مستوى مساحة العمل | ✅ نقطة نهاية جديدة |

**ملاحظتان تقنيتان مهمّتان:**

1. `Table.row_count` يُحدَّث عبر مهمة Celery دورية، أي أن الرقم **تقريبي وليس لحظيًا**.
   هذا مقبول لبطاقة إحصائية، لكن يجب ألا يُعرض في سياق يوحي بالدقة اللحظية.

2. سجل التغييرات على مستوى مساحة العمل هو أغلى بند في الاقتراح. `row_history` مُفهرس
   لكل جدول؛ تجميعه عبر مساحة عمل كاملة يحتاج استعلامًا مصمَّمًا بعناية وإلا صار الاستعلام
   أثقل من الصفحة نفسها.

## 5. التنفيذ المقترح على مرحلتين

### المرحلة الأولى — بدون أي تعديل على الخلفية
شريط الأرقام (٣ بطاقات من ٤) + «أكمل من حيث توقفت» + قائمة قواعد البيانات المحسّنة +
حذف البطاقتين الثابتتين.

هذه المرحلة **تُنجز بالكامل داخل `workspace.vue` ومكوّنات جديدة**، ولا تلمس الخلفية
إطلاقًا. وحدها كفيلة بتحويل الصفحة من قائمة إلى لوحة.

### المرحلة الثانية — بعد إقرار الأولى
إضافة `row_count` إلى الـ serializer (بطاقة الصفوف + عدّاد كل قاعدة)، ثم نقطة نهاية
التغييرات الأخيرة.

**التوصية:** البدء بالمرحلة الأولى وحدها. هي ٨٠٪ من الأثر المرئي بصفر مخاطرة على الخلفية،
وتُظهر الشكل النهائي فعليًا قبل الالتزام بتكلفة استعلام سجل التغييرات.

---

## 6. أسئلة مفتوحة تحتاج قرارك

1. **«أكمل من حيث توقفت»** — سجل محلي في المتصفح (بسيط، لكنه لا ينتقل بين الأجهزة) أم
   محفوظ في الخادم (ينتقل، لكنه يحتاج جدولًا جديدًا)؟ الاقتراح: محلي في المرحلة الأولى.
2. **آخر التغييرات** — هل هي فعلًا مطلوبة، أم أن الإشعارات الحالية تغطي الحاجة؟ هذا أغلى
   بند في الاقتراح ويستحق التأكد قبل بنائه.
3. **بطاقة الأعضاء** — تُعرض لكل المستخدمين أم للمشرفين فقط؟
